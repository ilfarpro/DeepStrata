# Roadmap: полная поддержка квантов Unsloth для DeepSeek-V4.1-Flash

Режим форка (с 2026-11-07): мы развиваем свою ветку Strata самостоятельно и обратно в
оригинал не вливаемся. Задачи, раньше задуманные как issue в апстриме, живут здесь
документами; решения о скоупе принимаем сами. При этом `main` периодически подтягивает
`origin/main` (Niko1221/Strata) — наши правки держим изолированно, чтобы синк оставался дешёвым.

Из 9 сетов `unsloth/DeepSeek-V4.1-Flash-1017-GGUF` Strata предлагала 3 (UD-Q8_K_XL,
UD-IQ1_S, UD-IQ1_M — все измерены). Оставшиеся 5 блокируют два правила движка:

- **A. Engram-читатель** (`src/dsv41/ds4_model.cu:3454`) знает MXFP8/Q6_K/IQ4_NL; таблицы
  UD-IQ2_XXS и UD-Q2_K_XL — Q5_K. Правка маленькая → [task-a-q5k-engram.md](task-a-q5k-engram.md).
- **B. Смешивание MXFP4** (`src/dsv41/ds4_model.cu:2418`): слой либо целиком MXFP4, либо
  целиком low-bit; у 4 сетов есть слои с MXFP4 down + 2/3-bit gate/up. Правка крупная →
  [task-b-mxfp4-down.md](task-b-mxfp4-down.md).

## Фаза 1 — UD-IQ2_XXS (правка A; самый нужный сет)

Сет ценен тем, что влезает туда, где XL-наборам тесно: ~165 GB весов против 298–306, эксперты
157 GB против 289.

1. Реализация по спеке [task-a-q5k-engram.md](task-a-q5k-engram.md): fmt Q5_K в цепочке
   `ds4_model.cu:3452` + проверка superblock-выравнивания (как Q6_K `eg_hd % 256`); разчёт
   строк и planner в `eg_issue`; деquant-ветка в `engram_dequant_tok_kernel`
   (`ds4_kernels.cu:1967`) + Metal-хук; сборки CUDA/HIP/SYCL/Metal. Новая ветка достижима
   только паком с Q5_K-таблицей — дефолтные пути byte-identical.
2. Валидация по чек-листу спеки на CUDA + gfx1200 (SHA-256 из `pins/iq2-files.json`).
3. Каталог: пины UD-IQ2_XXS, запись models (recipe "ud"), UD_SETS в `dsv41_fit` — заготовка
   в `catalog-prep-iq3.patch`. Перед работой: сверить коллизии имён с Qwen (`DEEPSEEK_KEPT`).
4. Docs: секция-отчёт («этот сет уже предлагался бы…»), строка Install, тесты
   (`test_setup_dsv41.py`, `test_launch.py`, `test_launch_dsv41.py`).

Критерий выхода: `strata launch --family deepseek41 --model UD-IQ2_XXS` работает на двух бэкендах.

## Фаза 2 — четыре 3-bit сета (правка B)

5. **Точка решения — теперь наша:**
   - «поддержка»: per-role диспетч (gate/up через ds4_iq, down через MXFP4) в GPU- и CPU-пути
     обоих бэкендов + снятие гарда;
   - «отказ заранее»: гард остаётся, паковка refuseит такие GGUF сразу, со списком слоёв и
     понятным сообщением (docs уже написаны); в каталоге сетов нет.
   Spec и цена каждой дороги — в [task-b-mxfp4-down.md](task-b-mxfp4-down.md).
6. Если поддержка — валидация по нарастающей сложности: UD-Q3_K_XL (MXFP8-таблица читается →
   тестируем только правило экспертов) → UD-IQ3_XXS, UD-IQ3_S (нужен ещё Q6_K — читается) →
   UD-Q2_K_XL (нужны обе правки A+B).
7. Каталог: 4 сета. Пины: `pins/iq3-files.json`, `pins/q2k-files.json`; UD_SETS-параметризация
   (`experts`/`expert_gb`/`expert_how`/`tp_alt`/`untimed`) уже в `catalog-prep-iq3.patch`.
8. Тесты и docs — шаблоном фазы 1.

Критерий выхода: все 5 сетов в каталоге и загружаются; либо осознанное «не поддерживаем» с
ранним понятным отказом.

## Риски и правила

- **Re-publish Unsloth'а**: пины актуальны на ревизии `8a6ec9cf` (2026-11-07); перед каждой
  скачкой — перевалидировать HEAD/SHA (`pins/rev-check*.txt` — образец проверки).
- **Синк с апстримом**: правки движка не переписывают чужие функции, а добавляют ветки,
  достижимые только нашими паками; тогда `git merge origin/main` остаётся механическим.
- Ни одной оценки скорости/качества без замера на конкретном железе; passed / failed /
  not run держим раздельно в записи каждой задачи.
- Все находки в спеках — статический анализ (чтение кода и заголовков шардов), прогонов GPU
  на дев-машине не было; любое «работает» появляется только после чек-листа на железе.
